  • Content/data: ₹28,400, ₹3,200 comparison, categories and percentages are BRD-format/representative interface content; not live account data, research evidence, or validated calculations.
  • States represented: static default only; budget-sheet entry and toast previews.

  • Assets: HTML plus screen-01-overview.jpg.

  • Approval status: Provisional/LOW; not approved for handoff.

HF-02: Food & Dining detail — provisional visual sample

  • Flow/story: F-01/WF-02 category detail; visual cue toward F-02.
  • Viewport/role: 390px mobile simulation; authorization Unknown.
  • Component set: app bar, amount summary, weekly bar chart, explanation panel, transaction list, correction preview control.
  • Content/data: ₹8,200 and comparison formats trace to the BRD/sample; weekly bar values, dates, merchants, and transaction rows are representative sample content, not observed or production data.
  • States represented: static default and back navigation only.
  • Accessibility checks: chart has a text alternative; headings and named buttons are present in source; semantic list structure, focus target, reflow, contrast over every visual state, and AT behavior are untested.
  • Assets: HTML plus screen-02-food-detail.jpg.
  • Open issues: correction is non-functional; no transaction detail, permissions, refund/reversal/pending variants, data status, error/recovery, or approved financial notation rules.
  • Approval status: Provisional/LOW; not approved for handoff.

HF-03: Set-budget sheet — simulated sample state

  • Flow/story: Partial F-03/WF-07; does not cover WF-06/WF-08.
  • Viewport/role: mobile bottom sheet; eligibility and role Unknown.
  • Component set: scrim, sheet, heading, preset-choice buttons, primary save button.
  • Content/data: three static amount choices; no custom amount, currency/range rule, current spend, alert configuration, or permission status.
  • States represented: open, visual selection, simulated save/toast, scrim/Escape close.
  • Accessibility checks: dialog name, initial focus, Escape, and focus return exist; no focus trap, explicit cancel/close, inert background, selected-state semantics, validation, pending/failure, or durable status.
  • Assets: HTML only; no separate capture/versioned state board.
  • Open issues: simulated success can imply persistence and must not be treated as production behavior.
  • Approval status: Blocked for production use.
