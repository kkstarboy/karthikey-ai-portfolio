User Flows and Task Flows — Provisional

Scope, evidence, and confidence

These flows translate BRD requirements and the provisional sitemap into testable interaction logic. They are not observed user behavior, approved screen designs, implemented system behavior, or production rules.

  • Sources: Starter BRD; approved Phase 03 artifacts; Phase 04 content inventory, study plan, and sitemap.
  • Missing inputs: Validated scenarios/stories, business/category/data rules, authentication/session model, permissions, architecture, technical constraints, notification/export policies, owners, research/usability evidence.
  • Confidence: BRD requirement presence is documented; flow sequencing, decisions, labels, states, and outcomes are Inferred/LOW.
  • State rule: Authentication, permission, empty, loading, partial, stale, offline, error, timeout, cancellation, recovery, and confirmation are considered wherever applicable.

2. User flows

Flow F-01 — Review spending

  • User: Provisional candidate user.
  • Trigger: Opens tracker from an existing app entry point (entry location Unknown).
  • Start: Authenticated/authorized access is assumed, not specified.
  • Success end: Person reaches a comprehensible, current summary or relevant detail; comprehension is not yet validated.
  • Alternate ends: Exit without action; switch period/category; seek help; data unavailable; permission denied.
  • Main route: Entry → authorization/data-status check → load current period → overview total/categories/comparison → optional category or insight detail → return/exit.
  • Decision points: Authorized? Data available/current? Categories/period present? Insight eligible? User chooses detail/action?
  • Errors/recovery: Loading/timeout/offline/stale/partial data; retry, explain status, preserve context, contact/help where defined.
  • Data/permissions: Account/transaction scope, period/timezone, amount/currency, category, comparison rules, insight basis, freshness.
  • Links: N-10/N-11/N-112/N-113/N-114; CI-003–006/008/013/016–017; FR1/5/6.
  • Evidence/confidence: BRD documented; route LOW.

Flow F-02 — Correct category

  • User: Authorized transaction viewer/editor — role is an assumption.
  • Trigger: Person notices a possibly incorrect category from overview/category/transaction context.
  • Start: Transaction detail with current category.
  • Success end: Change is confirmed and effect on future matching is explained.
  • Alternate ends: Cancel/no change; choose same category; future-use declined; correction rejected; permission denied.
  • Main route: Select transaction → load detail → choose change category → show available taxonomy → select category → decide whether future matching applies if supported → review/confirm → system validates/saves → confirmation and updated totals.
  • Decision points: Editable? Category available? Same as current? Apply to future? Save succeeds? Does summary recalculate?
  • Errors/recovery: Unknown merchant/category, duplicate/reversed/refunded/transfer transaction, concurrency, offline/timeout/save failure; retain prior state and provide retry/cancel/undo only if rules approve.
  • Data/permissions: Transaction ID/status, merchant identity, original/new category, source/confidence, user rule precedence, audit, propagation, undo, recalculation.
  • Links: N-1121/N-1122; CI-006–007/013/015–017; FR2–4.
  • Evidence/confidence: BRD §8.3/FR2–4; LOW sequencing and rules.

Flow F-03 — Set/change budget

  • User: Authorized user; account/role model Unknown.
  • Trigger: User chooses a category budget from Budgets, category detail, or optional insight cross-link.
  • Start: Budget list/detail or contextual action.
  • Success end: Valid budget saved with threshold/notification behavior understood and controlled.
  • Alternate ends: Cancel; edit/delete existing budget if approved; decline notifications; permission denied.
  • Main route: Select category → enter amount/period → explain currency/rollover/threshold rules → validate → review notification preference → confirm → save → show progress/confirmation.
  • Decision points: Existing budget? Valid amount/currency? Period rule? Notification permission/channel? 80%/100% threshold event already passed?
  • Errors/recovery: Invalid amount, duplicate budget, stale spend, notification denied, save failure, offline/timeout; preserve input where safe and allow retry/cancel.
  • Data/permissions: Category, currency, amount, period, current spend, thresholds, notification preference/consent, timestamps.
  • Links: N-12/N-121/N-122/N-153; CI-009/013–014/016–017; FR7–8.
  • Evidence/confidence: BRD requirements; LOW flow/rules.

Flow F-04 — Review recurring commitments

  • User: Provisional household/all candidate; permissions Unknown.
  • Trigger: Opens recurring payments from tracker.
  • Start: Recurring summary.
  • Success end: Understands candidate commitments and their status; correctness not assumed.
  • Alternate ends: No detected items/empty state; inspect item; seek correction/help; export if authorized; exit.
  • Main route: Open recurring → load detection results → show items/amounts/frequency/confidence where approved → select item → review basis/history → confirm/correct/dismiss only if supported → return.
  • Decision points: Data available? Item confidently recurring? Shared/sensitive item? Correction capability approved? Export chosen?
  • Errors/recovery: False positive/negative, irregular amount, duplicate merchant, cancelled subscription, missing history, data timeout; explain uncertainty and route correction/help without claiming detection accuracy.
  • Data/permissions: Merchant, amounts/dates, frequency, recurrence status/confidence, account role, correction/audit.
  • Links: N-13/N-131/N-132/N-14; CI-010/012–013/015–017; FR9–10.
  • Evidence/confidence: BRD §7.6/8.4/FR9; LOW.

Flow F-05 — Export/share monthly summary

  • User: Authorized account user — assumption.
  • Trigger: Chooses monthly record/export.
  • Start: Period/summary context.
  • Success end: Accurate authorized file generated and handled according to approved privacy/accessibility rules.
  • Alternate ends: Cancel; format unavailable; permission/re-auth fails; generation/share fails.
  • Main route: Choose export → select approved period/format/content if choices exist → privacy warning/data scope → re-auth if required → generate → verify status → save/share through approved mechanism → confirmation.
  • Decision points: Authorized? Re-auth required? Format approved? Sensitive fields included? Storage/share target available?
  • Errors/recovery: Stale/partial data, generation timeout, inaccessible output, storage permission, share cancellation; no silent partial file.
  • Data/permissions: Period, included accounts/transactions/categories, locale/currency, redaction, file metadata, retention, share target.
  • Links: N-14/N-141/N-151; CI-002/012–013/016–017; FR10.
  • Evidence/confidence: BRD §7.8/FR10; LOW.

Flow F-06 — Unusual-spending alert

  • User: Authorized user who has not opted out — assumption.
  • Trigger: System detects an eligible pattern; criteria Unknown.
  • Start: In-app insight or notification if authorized.
  • Success end: Person can understand basis, inspect data, dismiss, and control future alerts without judgment.
  • Alternate ends: Suppressed/not sent; dismissed; notification permission denied; pattern no longer current; user reports error.
  • Main route: Eligibility/privacy/permission checks → neutral message with context → open relevant detail → explain basis → optional action/dismiss/preferences.
  • Decision points: Sufficient data/confidence? Harm-sensitive context? Notification allowed? Duplicate/recent alert? User wants detail/action?
  • Errors/recovery: False positive, outdated amount, deep-link failure, missing data; explain uncertainty, preserve control, avoid alarmist language.
  • Data/permissions: Baseline window/rules, transaction/category, confidence, notification consent, suppression history.
  • Links: N-114/N-1121/N-153; CI-008/011/013–014/016–017; BRD §7.7.
  • Evidence/confidence: Business proposal only; LOW and Decision needed.
