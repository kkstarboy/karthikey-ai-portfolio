Design QA Against Brand and Style Reference — Provisional Audit

Purpose, references, and evidence boundary

This QA evaluates the available two-screen sample against the supplied alpha Airbnb-derived reference, the Phase 09 design-system mapping, and the accessibility review. It distinguishes objective reference deviations from subjective preference and cannot approve brand exceptions or production readiness.

  • Reference standard: Skills/09 Visual Design (UI)/DESIGN-airbnb.md, version alpha.
  • Product assets audited: smart-expense-tracker.html, two 780×1688 JPEGs, and sample-design-notes.md.
  • Phase 09 specifications audited: design-system-application.md, high-fidelity-mockups.md, and accessibility-review.md.
  • Missing authorities: current-app design system, approved Smart Expense Tracker brand/style/content standards, design-system/brand owner, accessibility target, platform matrix, and product/engineering/privacy/security decisions.
  • Research boundary: no participant testing or usability findings exist. Visual consistency does not establish usability or preference.

Severity for this audit: Critical = blocks safe/core/sensitive handoff; High = material accessibility, consistency, or repeated-component risk; Medium = local or bounded deviation requiring correction; Low = minor documented cleanup. This is design-risk severity, not participant evidence.

3. Deviation log

DQA-01: Primary text-bearing Rausch control contrast

  • Screen/component: Overview and budget sheet primary buttons.
  • Reference rule: Accessibility must not be overridden for brand aesthetics; white text uses Rausch primary in the reference.
  • Observed deviation: The referenced combination is itself insufficient for inspected 13px normal text under the WCAG 2.2 AA diagnostic: 3.52:1.
  • Severity: High/blocking.
  • Systemic/local: Systemic token-use issue.
  • Correction: Create/approve a text-bearing accessible primary token; darker #e00b41 is a 4.89:1 candidate, subject to rendered-state review.
  • Exception rationale: None approved.
  • Owner/status: Design-system/accessibility/brand / Open.

DQA-02: Custom palette, gradient, shadow, radii, and type sizes

  • Screen/component: Summary card, category icons, screen typography, phone/sample surfaces.
  • Reference rule: Use supplied color/type/radius/spacing/elevation tokens and document justified exceptions.
  • Observed deviation: Sample adds a dark finance gradient, four category colors, custom two-part shadow, 12/18/44px radii, and local type sizes.
  • Severity: Medium; High if these become repeated production tokens without governance.
  • Systemic/local: Potentially systemic.
  • Correction: Separate staging-only styles, map product styles to named tokens, and submit finance-specific semantic tokens/components for owner review.
  • Exception rationale: Fintech density/data differentiation is documented in sample notes but not approved.
  • Owner/status: Product design/design-system/brand / Open.

DQA-03: Detached custom components

  • Screen/component: Summary card, category/transaction rows, tab bar, chart, budget sheet, toast.
  • Reference rule: Use variants/states and maintain library connections; avoid detached duplicates.
  • Observed deviation: All components are local HTML/CSS with no authoritative library link or stable product component IDs.
  • Severity: High/systemic.
  • Systemic/local: Systemic.
  • Correction: Resolve NCR-01–05, bind designs to approved components/tokens, and preserve variant/state names.
  • Exception rationale: No product library was supplied; local sample was appropriate only as a provisional concept.
  • Owner/status: Design-system/product/engineering / Blocked by missing library/owners.

DQA-04: Stale sample status documentation

  • Screen/component: sample-design-notes.md.
  • Reference rule: Source versions, state, and limitations must remain current.
  • Observed deviation: Notes stated G01 was pending and that no approved mid-fidelity baseline existed after G01–G08 approvals.
  • Severity: Medium traceability issue.
  • Systemic/local: Local documentation.
  • Correction: Updated status on 2026-07-24 to record G01–G08 approvals, Phase 06’s provisional baseline, Phase 07 NOT READY status, no Phase 08 research evidence, and pending G09.
  • Exception rationale: Not applicable.
  • Owner/status: Phase 09 agent / Corrected; verify hash/version in future reviews.

DQA-05: Missing component and interaction states

  • Screen/component: All sample components and WF-00–17/WF-20–22.
  • Reference rule: Use component variants/states; high-fidelity designs must include required happy, alternate, permission, error, recovery, responsive, and extreme-data states.
  • Observed deviation: Default states dominate; loading, empty, partial, stale, denied, validation, pending, failure, timeout, conflict, export, recurring, and unusual-pattern flows are absent.
  • Severity: Critical/systemic.
  • Systemic/local: Systemic coverage gap.
  • Correction: Resolve Phase 06 rules and PRE-01–07, then build/version/review the complete state matrix.
  • Exception rationale: Guardrail prevents polishing unresolved logic; omission is disclosed, not approved for handoff.
  • Owner/status: Product/design/engineering/risk / Blocked.

DQA-06: Modal, selection, focus, list, and status semantics

  • Screen/component: Budget dialog, screen switch, financial lists, tab bar, toast.
  • Reference rule: Accessibility and inclusive behavior must be preserved; visual appearance alone cannot communicate interaction.
  • Observed deviation: A11Y-02–08 document incomplete selected/current state, focus containment/destination, list semantics, icon treatment, durable status, and responsive evidence.
  • Severity: High/systemic.
  • Systemic/local: Cross-component.
  • Correction: Apply the accessibility-review.md remediation plan and retest rendered components.
  • Exception rationale: None approved.
  • Owner/status: Accessibility/design-system/engineering / Open.

DQA-07: Responsive and platform model does not match a governed product matrix

  • Screen/component: Entire sample.
  • Reference rule: Check mobile/tablet/desktop/wide behavior, platform conventions, localization, density, and reflow.
  • Observed deviation: One 760px breakpoint and a decorative 390px phone stage; reference uses 744/1128/1440 bands, but neither is an approved product matrix.
  • Severity: High.
  • Systemic/local: Systemic.
  • Correction: Define supported platforms/breakpoints/viewport and accessibility settings, then render and inspect every required variant.
  • Exception rationale: Existing sample was intentionally mobile-oriented, not a responsive production design.
  • Owner/status: Product/platform/design/accessibility / Open.

DQA-08: Content, financial notation, and claim governance incomplete

  • Screen/component: Totals, comparisons, insight, transactions, budget confirmation, preview toasts.
  • Reference rule: Content style, terminology, errors, and state messages must be consistent and traceable.
  • Observed deviation: Representative chart/transaction values, “saved” simulation, minus-sign spending notation, calculation language, period/freshness, and error/permission content lack approved contracts.
  • Severity: Critical for production financial status; Medium as disclosed prototype content.
  • Systemic/local: Systemic content/data dependency.
  • Correction: Obtain product/data/content/privacy/legal rules; label simulation; remove or qualify unsupported certainty; review extreme/localized values.
  • Exception rationale: Representative content prevents lorem ipsum and is disclosed in artifacts; it is not approved production content.
  • Owner/status: Product/data/content/privacy/legal / Blocked.
