Mid-Fidelity Wireframes — Provisional Flow-Complete Specification

Scope, baseline, and limitations

These Markdown wireframes define content hierarchy, screen/state inventory, and transitions for review. They are not pixel layouts, high-fidelity UI, interactive prototypes, implemented behavior, validated usability, or production specifications.

  • Exploration baseline: C-01 Overview First covers all six provisional flows because it provides a common navigation frame. This is an artifact choice, not a product selection.
  • Comparison branch: C-02 Guided Review remains as WF-20–WF-22 for later comparative testing.
  • Conditional context: C-03 Transaction Context is represented through contextual entry/cross-link behavior, pending parent-app access.
  • Sources: Approved Phase 04 IA/flows; approved Phase 05 concepts/low-fidelity structures; BRD.
  • Missing: Current app shell/design system foundations, platform/viewport matrix, approved stories/rules, APIs, permissions, data definitions, accessibility target, localization, feasibility review, and user testing.
  • Confidence: Screen/interaction proposals are Inferred/LOW; BRD feature presence is business-documented.

5. Annotations summary

  • Stable interaction/state rules are detailed in Output/phase-06/interaction-annotations.md.
  • Focus order follows visual/semantic reading order; dynamic status is announced; color is never the only state cue.
  • Values require period, currency, locale, source/scope, freshness, and calculation rules.
  • Any proposed confirmation, undo, dismiss, or correction not explicit in BRD is labeled as a requirement candidate for owner review.
  • Responsive behavior is single-column first; wider arrangements cannot reorder reading/focus or hide essential state.
