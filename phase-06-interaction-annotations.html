1. Interaction annotation set

INT-01 — Enter tracker

  • Trigger: Activate Spending entry from the parent app.
  • Preconditions: Authenticated access, feature state, and consent model Unknown.
  • System response: Verify authorization and data availability before showing financial content.
  • Feedback/result: WF-00 for orientation when required; otherwise WF-01 with status/freshness.
  • Error/recovery: WF-17 re-auth/deny or WF-16 unavailable; preserve intended route only when safe.
  • Keyboard/focus: Focus first meaningful heading; skip link/landmarks where platform supports; no focus on hidden data.
  • Responsive: Single-column; navigation label remains explicit.
  • Dependencies/confidence: Auth/privacy/parent app / LOW.

INT-02 — Change period

  • Trigger: Activate period selector on WF-01/02/06/11.
  • Preconditions: Available-period rules/data Unknown.
  • System response: Load selected period; keep prior data visibly stale/pending or replace with loading shell according to approved policy.
  • Feedback/result: Announce new period and load status; update all dependent totals/content atomically where possible.
  • Error/recovery: On failure retain prior period/data with explicit state; retry/cancel.
  • Keyboard/focus: Selector operable by standard controls; focus remains/returns predictably; result heading/status announced.
  • Dependencies/confidence: Period/timezone/data API / LOW.

INT-03 — Open category or transaction

  • Trigger: Activate category row or transaction row.
  • Preconditions: Row is authorized and has stable ID.
  • System response: Navigate to WF-02 or WF-03; load scoped content.
  • Feedback/result: Destination identifies period/category/transaction and status.
  • Error/recovery: Missing/deleted/reversed item → safe unavailable state, back to source, no stale sensitive preview.
  • Keyboard/focus: Entire row is one semantic target; visible focus; avoid nested conflicting actions.
  • Dependencies/confidence: Navigation/data identity / LOW.

INT-04 — Start category change

  • Trigger: Activate Change category on WF-03.
  • Preconditions: Edit authorization and transaction eligibility.
  • System response: Open WF-04 as full page or modal/sheet after platform decision; load approved taxonomy/current value.
  • Feedback/result: Current category selected; transaction context visible.
  • Error/recovery: Unauthorized/non-editable → explanation and safe return/help.
  • Keyboard/focus: Container has accessible name; initial focus heading/current value; Escape/back behavior does not save; return focus to trigger.
  • Dependencies/confidence: Permission/taxonomy/platform component / LOW.

INT-05 — Review and confirm category change

  • Trigger: Choose a different category and activate Review/Confirm.
  • Preconditions: New category valid; future-use option resolved.
  • System response: Validate, present exact before/after and future effect, then submit once.
  • Feedback/result: WF-05 pending → success/failure; successful data refresh behavior Unknown.
  • Error/recovery: Same value, unavailable category, conflict, offline, timeout, duplicate submit; prior state authoritative until success.
  • Keyboard/focus: Field error linked/announced; pending status live; success heading focused/announced.
  • Dependencies/confidence: FR3–4 rules/API/audit / LOW.

INT-06 — Set/change budget

  • Trigger: Activate Set/change from WF-06 or category context.
  • Preconditions: Authorization, approved category, currency, existing-budget rules.
  • System response: WF-07; validate amount/period; keep notifications separately controllable where policy permits.
  • Feedback/result: Review then WF-08 pending/success/failure.
  • Error/recovery: Invalid/zero/negative/extreme amount, duplicate budget, stale spend, notification denial, timeout; retain safe input, prevent duplicate save.
  • Keyboard/focus: Proper input label/instructions; numeric keyboard not sole input method; error summary and field focus.
  • Dependencies/confidence: Budget/notification lifecycle / LOW.

INT-07 — Inspect/qualify recurring item

  • Trigger: Activate row on WF-09.
  • Preconditions: Authorized item; detection status available.
  • System response: WF-10 with evidence/history and explicit detected/confirmed/unknown status.
  • Feedback/result: Optional Confirm/Not recurring actions only if approved.
  • Error/recovery: Irregular/duplicate/cancelled/sensitive/shared item; explain uncertainty, help, safe return.
  • Keyboard/focus: Status expressed in text; history list semantic; no calendar-only representation.
  • Dependencies/confidence: Recurrence rules/permissions/correction API / LOW.

INT-08 — Create/export monthly record

  • Trigger: Activate export from WF-01/09 then Create file on WF-11.
  • Preconditions: Authorization, allowed period/format/scope, current data, storage/share policy.
  • System response: Show privacy/scope; re-auth if required; WF-12 progress; create once.
  • Feedback/result: Ready/failed/cancelled status; Save/Share only after success.
  • Error/recovery: Partial/stale, format unavailable, re-auth denied, generation timeout, storage permission, share cancelled; no ambiguous/partial file.
  • Keyboard/focus: Progress/status announced; generated file has accessible structure requirements; focus to result.
  • Dependencies/confidence: Export/security/privacy/accessibility / LOW.

INT-09 — Open/dismiss unusual pattern

  • Trigger: Activate in-app insight or authorized notification deep link.
  • Preconditions: Eligibility, current data, notification consent, suppression rules.
  • System response: WF-13 with period/baseline/basis and relevant detail link.
  • Feedback/result: Inspect, dismiss, or preferences; no forced action.
  • Error/recovery: Stale/false/deep-link failure/missing transaction; explain limitation and safe fallback.
  • Keyboard/focus: Neutral content, status not color-only; notification destination heading focused.
  • Dependencies/confidence: Anomaly/content/notification policy / LOW.

INT-10 — Guided review navigation

  • Trigger: Next/Back/Skip/Full overview/Exit on WF-20–22.
  • Preconditions: Eligible step sequence; persistence rules Unknown.
  • System response: Move within current review without hiding full-view/exit; no fixed progress claim unless total steps known.
  • Feedback/result: Step context and data status announced; Finish may end with no action.
  • Error/recovery: No eligible pattern, stale step, resume conflict, deep-link failure; skip safely or full overview.
  • Keyboard/focus: Focus destination heading; preserve logical history; reduced motion/no required animation.
  • Dependencies/confidence: Step eligibility/state model / LOW.

INT-11 — Save preferences

  • Trigger: Change alert controls on WF-14 and Save.
  • Preconditions: Platform permission and server/device preference model.
  • System response: Validate; reconcile platform denial; submit once.
  • Feedback/result: Pending/saved/failed with actual effective state.
  • Error/recovery: Conflict across device/account, offline, denied channel; prior effective setting remains clear.
  • Keyboard/focus: Standard controls and labels; status announced; no color-only on/off.
  • Dependencies/confidence: Notification platform/privacy / LOW.

5. Accessibility behavior

  • Use semantic headings, lists, controls, groups, and status regions; never encode meaning by spatial position or color alone.
  • Maintain logical focus/read order across single- and multi-region responsive layouts.
  • On navigation, focus the destination heading; on modal/sheet open, focus its heading; on close, return focus to the trigger.
  • Announce loading, partial/stale, validation, pending, success, failure, and cancellation without excessive repetition.
  • Provide visible focus, keyboard/switch operability where applicable, adequate target sizes, text scaling/reflow, magnification support, and reduced-motion behavior.
  • Present chart/pattern information as structured text and lists; provide full merchant/category/value relationships.
  • Do not auto-advance guided steps or dismiss critical messages on a timer.
  • Use plain-language, non-judgmental errors and explanations; avoid exposing sensitive financial details in notifications or unauthorized states.

These are requirement candidates pending target standards, platform rules, component review, and assistive-technology testing; no conformance claim is made.
